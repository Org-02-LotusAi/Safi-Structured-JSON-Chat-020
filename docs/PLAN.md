## Task 2: OpenAI Worker (`worker/`)

Goal: NATS subscriber that turns a validated `chat.request` into a live OpenAI Responses call and replies with a validated `chat.result` or typed `chat.error`.

- Package `@safi/worker`, entry `worker/src/main.ts` (reads env, loads registry — fails fast on registry error or missing `OPENAI_API_KEY`, connects NATS with reconnect, subscribes `safi.chat.request.v1` queue `safi-openai-worker`, graceful SIGINT/SIGTERM drain). Core logic in `worker/src/handler.ts` exported as `createHandler({registry, openai, model, maxOutputTokens, logger, now})` → `handle(envelopeJson: unknown): Promise<ResultEnvelope|ErrorEnvelope>` so it is unit-testable without NATS. `worker/src/openai-client.ts` wraps the SDK: `new OpenAI({apiKey, baseURL, maxRetries:0, timeout})`.
- Handler steps (each failure → typed `chat.error` built with `buildErrorEnvelope`, never throws to NATS):
  1. Ajv-validate request envelope (`schema_rejected`/`ingress_rejected` style code `ingress_rejected`).
  2. Routing: `to_guid` must equal OPENAI_SERVICE_GUID, `from_guid` PILOT_SENDER_GUID, context equals PILOT_CONTEXT → else `routing_rejected`.
  3. Schema: `schema_ref` must exist in registry with matching version and `schema_sha256` → else `schema_rejected` (no OpenAI call).
  4. Idempotency by `message_id`: in-memory LRU (max 500, TTL 15 min). Completed → return the cached reply (no second OpenAI call). In-flight → await the same promise. Expose a counter `openaiCalls` for tests.
  5. Build input: system instruction (short, states it must answer only within the JSON schema, it is a guest service and cannot change routing), then `history` items as `{role, content}` and the current user text. `client.responses.create({model, input, text:{format:{type:"json_schema", name: <schema id with dots→underscores>, schema, strict:true}}, store:false, max_output_tokens})`.
  6. Map outcomes: response.status `incomplete` → `incomplete` (retryable false); any output content item of type `refusal` → `refusal`; `output_text` not parseable JSON or not an object → `invalid_model_output`; parsed object fails Ajv for the selected reply schema → `invalid_model_output` (message names the failing path only, not content). SDK errors: `RateLimitError` (429) → `rate_limited`; `APIConnectionTimeoutError` → `upstream_timeout`; `APIConnectionError` → `upstream_network`; other `APIError` → `upstream_error`. All messages run through `redactSecrets`.
  7. Success → `buildResultEnvelope` with `body`, `model` (response.model), `openai_request_id` (response `_request_id` or `x-request-id`), `usage`; then Ajv-validate the full result envelope; if it fails → `invalid_model_output`. Never coerce.
  8. Validate the error envelope too before replying.
- Logging: pino, log message_id, conversation_id, schema, outcome, error code, openai_request_id, latency; never text/history/reply.
- Tests (`tests/worker.*.test.ts`): use a **fake OpenAI HTTP server** (`tests/helpers/fake-openai.ts`, node:http on a random port, implements `POST /v1/responses` with a scripted queue of behaviors: valid summary JSON, valid tasks JSON, extra-field JSON, malformed JSON text, refusal item, `status:"incomplete"` with `incomplete_details.reason:"max_output_tokens"`, HTTP 429, hang beyond timeout, socket destroy). Point the real `openai` SDK at it via `baseURL`. Also record the request bodies it receives to assert `store:false`, `max_output_tokens<=512`, `text.format.strict===true`, `type:"json_schema"`, no `tools`, history included. Cover: success both schemas; routing/schema rejections make zero fake-server calls; each failure maps to its distinct code; duplicate message_id → one upstream call (sequential and concurrent); plus one integration test through real nats-server (helper from Task 1) using the real `main`-style wiring (export a `startWorker({natsUrl, ...})` function from `worker/src/service.ts` that main.ts calls).

Done when tests green, `tsc -b worker` clean. Commit.

## Task 3: Fastify server (`server/`) + start script

Goal: authenticated HTTPS bridge that binds identity/context server-side, enforces limits, calls the worker over NATS, double-checks the reply, writes the audit receipt, serves the SPA.

- Package `@safi/server`. `server/src/app.ts` exports `buildApp(deps)` (deps: config, registry, natsRequester interface `{request(subject, data, timeoutMs): Promise<Uint8Array>}`, auditPublisher interface `{publish(receipt): Promise<void>}`, clock, usage store) so routes are testable with `app.inject`. `server/src/main.ts` wires real NATS (Core request + JetStream; ensures stream `SAFI_CHAT_AUDIT` exists with the CONTRACTS config, creating/updating it), HTTPS options from TLS files (refuse to start without TLS unless `TRUST_PROXY=true`, in which case plain HTTP behind a TLS proxy and cookies still `secure`), static `web/dist` (if missing, serve a tiny page saying "run npm run build").
- Auth: `POST /api/login {username,password}` (strict body), constant-time compare against env (`crypto.timingSafeEqual` on SHA-256 digests), login throttle (5 failures/5 min per IP). Session store in memory: random 32-byte id, signed cookie `safi_session` (httpOnly, secure, sameSite=strict, path=/, maxAge TTL). One pilot user at a time: a new login revokes prior sessions. Role `pilot_user` held server-side only. `POST /api/logout`, `GET /api/session` → `{authenticated, username, conversation_id, expires_at}`. CSRF: require header `x-safi-csrf` equal to a per-session token returned by `/api/session` and `/api/login` on all state-changing `/api/*` POSTs except login.
- Conversations: session owns a set of conversation ids (server-generated); `POST /api/conversations` creates a new one (resets that conversation's history); history per conversation kept server-side: last `MAX_TURNS` (8) turns (user text + assistant `reply` string), never cross-session.
- `POST /api/chat`: order of checks — auth → CSRF → Ajv browser body (400 `ingress_rejected`) → conversation ownership (403 `routing_rejected`) → schema id in registry + `ui_choice` + optional sha256 match (400 `schema_rejected`) → idempotency by `(session, request_id)`: completed → return cached response (no NATS); in-flight → 409 `duplicate_in_flight`; previously ambiguous (timed out / no reply) → 409 `upstream_ambiguous` "outcome unknown; send a new message" (never re-sent) → per-user rate (10/min sliding window, 429 `user_rate_limited`) → global API-call cap (persisted usage.json; 429 `cap_exceeded`) → build request envelope (server-side GUIDs/context/schema_ref/sha256, fresh message_id, history) → Ajv-validate it → increment usage counter (persist) → NATS request 30 s. NATS errors: no responders / timeout → 504 `worker_unavailable` (timeout after publish marks the request_id as ambiguous). Reply checks: parse JSON; Ajv result-or-error envelope; `in_reply_to === message_id`, `conversation_id` equal, `from_guid === OPENAI_SERVICE_GUID`, `to_guid === PILOT_SENDER_GUID`, context equal, schema_ref+sha256 equal; result body re-validated with the registry Ajv validator (independent check). Any mismatch → 502 `invalid_model_output` (body never shown as compliant). Typed worker errors pass through with HTTP mapping (refusal 422, incomplete 422, rate_limited 503, upstream_timeout 504, upstream_network 502, upstream_error 502, invalid_model_output 502, schema_rejected 400, routing_rejected 403). On success append turn to history. Publish audit receipt (await JetStream ack) before responding; on failure respond with `audit:"failed"`.
- `GET /api/schemas` → registry entries with `ui_choice` (id, version, sha256, label, and the schema JSON for display). `GET /api/status` (auth) → `{api_calls_used, api_call_cap, user_rate_per_min, model, nats:"connected"|"disconnected", worker: last-known}` and a public unauthenticated `GET /healthz`.
- Security headers (CSP default-src 'self', no inline scripts; X-Content-Type-Options; Referrer-Policy; frame-ancestors 'none'), body limit, pino redaction per CONTRACTS.
- `scripts/start.mjs`: runs built `worker/dist/main.js` and `server/dist/main.js` as two child processes with prefixed logs, forwards signals, exits if either dies. `scripts/gen-dev-cert.mjs` (`npm run certs:dev`): self-signed cert for localhost/127.0.0.1 into `infra/certs/` using the `selfsigned` npm package (devDependency) or node + openssl if present.
- `openapi.yaml` (OpenAPI 3.1) documenting all `/api/*` endpoints and the schemas (reference `schemas/*.json`).
- Tests (`tests/server.*.test.ts`) with `app.inject` and fake NATS requester (deterministic) covering: auth required; bad login; session revocation on second login (old cookie → 401); CSRF missing → 403; unknown body fields (from_guid, context, role, subject, model, schema) → 400 and NATS requester never called and usage counter unchanged (A06/A08); unknown schema id / mismatched sha / raw schema → 400 no NATS (A07); foreign conversation id → 403; reply with wrong in_reply_to / conversation / from_guid / schema digest → 502 not shown as ok (A08 cross-conversation substitution); reply body with extra field → 502 `invalid_model_output` (A09); worker error codes map to distinct HTTP+codes (A10); no-responders and timeout → 504 `worker_unavailable` and the retried same request_id → 409 `upstream_ambiguous` with no second NATS request (A11/A12); completed duplicate returns cached with no second NATS request (A12); rate limit 11th request in a minute → 429 before NATS; cap reached → 429 before NATS, persisted across `buildApp` re-creation; history bounded to 8 turns and sent in envelope; audit publish failure → `audit:"failed"`. Plus one integration test: real nats-server + real worker (`startWorker` from Task 2 pointed at the fake OpenAI server) + `buildApp` with real NATS adapters: login → chat summary → chat tasks → receipt present in JetStream stream; stop worker → 504; restart worker → success.

Done when tests green, `npm run build` builds server/worker, `npm run start` with dev certs and a local nats-server serves `https://localhost:8443/healthz`. Commit.

## Task 4: Web UI (`web/`)

Goal: the SAFI Chat surface a non-developer can use.

- Vite + React + TS + Tailwind (v4 via `@tailwindcss/vite` or v3 — pick what works with pinned versions) + shadcn/ui-style primitives (Button, Card, Badge, Select/Tabs, Input — copy-in components under `web/src/components/ui/`, using `class-variance-authority`, `clsx`, `tailwind-merge`), `@assistant-ui/react` using `useLocalRuntime(adapter)` and `AssistantRuntimeProvider` + the assistant-ui Thread primitives (verify the exact current API from the installed package's type definitions — do not guess).
- Screens: Login (username/password, clear error text). Chat: header with product name "SAFI Chat", schema selector (from `GET /api/schemas`, only `ui_choice` entries; shows label + id@version), usage meter (`api_calls_used / cap`), "New conversation" and "Sign out" buttons. Thread area (assistant-ui). Each assistant message renders: the `reply` text prominently; for tasks schema a task list with priority badges; a collapsible "Structured data" panel showing the pretty-printed JSON body; a metadata row: Schema ID, version, SHA-256 (shortened with copy/full on hover), validation badge "Ajv 2020: PASS" (green) for envelope+body, model, OpenAI request id, audit status. Errors render as an assistant message styled as an error card with the error code, human-readable explanation per code (e.g. refusal → "The model declined to answer", worker_unavailable → "The AI worker is offline — try again shortly", upstream_ambiguous → "We could not confirm whether the last request completed; please send a new message"), and a "REJECTED — not schema-compliant" label for `invalid_model_output`. Never show an error as a success.
- ChatModelAdapter `run({messages, abortSignal})`: takes the last user message text, generates `request_id` (crypto.randomUUID), POSTs `/api/chat` with `{request_id, conversation_id, schema_id, schema_sha256, text}` + CSRF header, `credentials:"same-origin"`; returns content with text + metadata (use message `metadata.custom` or a custom content part — whichever the installed assistant-ui version supports; verify). On 401 → back to login.
- Session reload: on page load call `/api/session`; if authenticated, go straight to chat (thread UI resets on reload is acceptable; server history continues for the conversation — show a small note "Context: last 8 turns kept on the server for this conversation").
- Accessibility: labels, keyboard submit, focus states, responsive to phone width. Production build into `web/dist`, no inline scripts (CSP), no secrets in bundle.
- Vitest component tests are optional; required: `npm -w web run build` and `tsc --noEmit` clean. Dev proxy in `vite.config.ts` to `https://localhost:8443` (secure:false) for `npm -w web run dev`.

Done when build is clean and the built SPA served by the server lets you log in and chat against the integration stack (fake OpenAI) — verify manually by running the stack and fetching pages / or via a quick Playwright smoke. Commit.
